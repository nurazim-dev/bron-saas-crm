# Decision Log (DECISIONS.md)

This document records architectural and technical decisions, ambiguity resolutions, and spec amendments in chronological order.

| Date | ID | Decision | Reason / Context |
| :--- | :--- | :--- | :--- |
| 2026-11-14 | DEC-001 | Use `typescript@~6.0.3` and `eslint@^9.39.5` across workspaces instead of `typescript@7.0.2` / `eslint@10` | `typescript-eslint@8.72.2` declares peer dependency `typescript: >=4.8.4 <6.1.0`, and `eslint-plugin-react` (used by `eslint-config-next@16.4.6`) requires `eslint: ^9.7`. Using TypeScript 6.0.3 and ESLint 9.39.5 satisfies all peer dependencies cleanly with zero warnings while keeping the latest stable compatible toolchain. |
| 2026-11-14 | DEC-002 | Use Node.js native `process.loadEnvFile()` in `backend/src/config/env.ts` | Node.js >= 22 provides built-in `.env` file loading (`process.loadEnvFile`), avoiding an extra runtime dependency while preserving precedence for already-set environment variables. |
| 2026-11-14 | DEC-003 | Disable `cacheComponents` and `partialPrefetching` experimental flags generated by `create-next-app@16.4.6` template | Keeps Next.js 16 App Router behavior predictable for standard dynamic SSR/CSR flows and API proxy rewrites in the MVP. |
| 2026-11-14 | DEC-004 | Configure Prisma 7 (`7.10.1`) with `prisma.config.ts`, `provider = "prisma-client"` (output `src/generated/prisma`), and `@prisma/adapter-pg` (`pg`) | Follows Prisma 7's official architecture where datasource URLs live in `prisma.config.ts` and runtime queries use driver adapters (`@prisma/adapter-pg`). `prisma migrate status` reports zero drift with the hand-written exclusion and `CHECK` constraints migration. |
| 2026-11-14 | DEC-005 | Documented uses of `prismaUnfiltered` (§3.3) | `prismaUnfiltered` is exported from `backend/src/lib/prisma.ts` and used ONLY in: (1) `backend/prisma/seed.ts` (clearing and seeding demo data), (2) `backend/tests/helpers/db.ts` (`truncateAllTables` between tests) and `backend/tests/integration/soft-delete.test.ts` / `auth-company.test.ts` (verifying soft-deleted rows / atomic rollback), (3) `backend/src/modules/auth/auth.service.ts` & `company.service.ts` (checking global uniqueness of `User.email` and `Company.slug` across soft-deleted rows per §3.3), and (4) `backend/src/modules/staff/staff.service.ts` (restoring a soft-deleted `MASTER` of the same company when recreated with the same email, and checking global email uniqueness). |
| 2026-11-14 | DEC-006 | Implement `backend/scripts/db-reset.ts` via schema recreation + `prisma migrate deploy` + `seed.ts` after verifying localhost & non-production | Enforces the localhost and non-production safety guards and resets the local `public` schema deterministically without interactive prompts. |
| 2026-11-14 | DEC-007 | Name the refresh token cookie `zapis_rt` and include a unique `jti` + `typ` claim in JWTs | Prevents access/refresh token confusion (`typ: "access"` vs `"refresh"`), guarantees every rotated refresh token is distinct (`jti: randomUUID()`), and scopes the `httpOnly` cookie strictly to `Path=/api/v1/auth` with `SameSite=Lax`. |
| 2026-11-14 | DEC-008 | Clean up `MasterService` and `WorkingHours` links when soft-deleting a Service or Staff member | Pure link/config tables carry no business history (§3.1); removing links on soft-delete keeps `serviceIds` and `workingHours` clean while historical `Appointment` rows still retain `serviceId` and `masterId` references. |
| 2026-11-14 | DEC-009 | Lock master rows in deterministic lexicographical UUID order (`lockMastersForUpdate`) inside `prisma.$transaction` on appointment create/update/restore | Guarantees deadlock-free `SELECT id FROM "User" WHERE id = ... FOR UPDATE` locking when an appointment is reassigned from one master to another concurrently (BR-1). |
| 2026-11-14 | DEC-010 | Return `409 CONFLICT` when a client phone reaches 3 upcoming `SCHEDULED` appointments in a company, and include `maxAdvanceDays` in `GET /public/companies/:slug` | Keeps the per-phone booking cap (`409 CONFLICT`) distinct from slot conflicts (`409 SLOT_ALREADY_BOOKED`), schedule violations (`422 SLOT_NOT_AVAILABLE`), and IP rate limits (`429 RATE_LIMITED`), while giving the public booking UI (`Phase 9`) the company's `maxAdvanceDays` for its date strip. |
| 2026-11-14 | DEC-011 | Scope `AuthBootstrap` to `/login`, `/register`, and `/dashboard/layout.tsx` instead of root `app/layout.tsx` | Ensures public routes (`/b/[slug]`, `/`) never execute session-refresh requests or bundle auth/dashboard state (`Phase 9 Task 4`). |
| 2026-11-14 | DEC-012 | Configure Playwright (`@playwright/test@1.65.1`) in `frontend/playwright.config.ts` with automatic `webServer` management for both `backend` (`:4000`) and `frontend` (`:3000`) | Allows `npm run test:e2e` to run deterministically in local development and GitHub Actions CI without manual background server orchestration. |
| 2026-11-14 | DEC-013 | Centralize all backend current-time reads in `backend/src/lib/clock.ts` (`now()`, `FakeClock`) and enforce via ESLint `no-restricted-syntax` | Satisfies v2 Non-Negotiable #6: business logic and JWT verification (`clockTimestamp`) read time solely through `clock.ts`, allowing deterministic time travel in unit and integration tests without flakiness. |
| 2026-11-14 | DEC-014 | Upgrade any-available-master booking (`"ANY"`) from client-side slot merging to full server-side **BR-12** candidate resolution | In v1, `"ANY"` merged slots on the frontend and submitted a single `masterId`. Under BR-12, `GET /public/companies/:slug/availability` computes the server-side union of free slots when `masterId` is omitted or `"ANY"`, and `POST /public/companies/:slug/appointments` orders candidates by `(fewest appointments on that local day ASC, id ASC)`, locking strictly one master at a time per transaction and falling back across remaining candidates on `SLOT_ALREADY_BOOKED` / `SLOT_NOT_AVAILABLE`. |
| 2026-11-14 | DEC-015 | Shrink `BusinessType` enum to `BARBERSHOP | BEAUTY_SALON` (default `BARBERSHOP`) via guarded migration `20261114124000_niche_narrowing_business_type` | Satisfies v2 Non-Negotiable #11 and §4.4: raises an explicit PostgreSQL exception if any row still holds `AUTO_SERVICE` or `OTHER`, recreates the enum with only `BARBERSHOP` and `BEAUTY_SALON`, and removes all auto-service (`СТО`) remnants across backend, frontend, tests, and docs. |
