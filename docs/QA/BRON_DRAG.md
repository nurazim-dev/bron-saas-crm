# Phase 2 — перенос в календаре

Реализован первый вариант drag/drop для дневной сетки.
- Перенос на время/мастера, подтверждение перед HTTP PATCH.
- Сохранение цены/состава, проверка услуг мастера, сообщение об ошибке.
- Повторная проверка конфликта сервером, блокировка кнопки во время запроса.
- Staff-предупреждения о выходе за смену/перерыв/отсутствие отображаются после переноса.
- Телефон/клавиатура: перенос через существующую форму редактирования.

Проверки:
- npm run gate: exit 0, 173 backend tests / 36 files, typecheck/lint/build/guard.
- После изменения drop-handler: frontend build и lint повторены успешно.
- Chromium calendar.spec.ts: 2 passed, exit 0.
- Реальные native dragTo: отмена и успешный перенос 10:00 → 14:00.
- Проверены сохранённые через API время/цена/состав и неизменность после отмены.
- Конфликт: dispatchEvent drag/drop → другой клиент занимает время → подтверждение
  получает настоящий 409; исходная запись сохраняется.
- Сохранились проверки 360/390/768/1024/1440 и восстановления после 503.
- Скриншот artifacts/bron-drag/moved-desktop.png просмотрен.
- Артефакты gate-summary.json/e2e.log в artifacts/bron-drag.
- Проверки использовали zapis_test. Dev/production БД не менялись, миграций нет.

Ограничения:
- Повторное native dragTo из уже перенесённой карточки при прокрутке в тесте не
  открыло диалог. Причина не устранена; dispatchEvent не доказывает исправление
  этого сценария. Полная готовность drag-and-drop не заявляется.
- Нет drag между датами/неделями, только дневная сетка с шагом 30 минут.
- Перенос на другого мастера реализован, но отдельный E2E для него не выполнен.
- Новые статусы, пакеты и цены мастеров остаются в Phase 2.
- Полный E2E-набор не запускался; старые pg/NO_COLOR warnings сохраняются.
- Предыдущие незакоммиченные изменения сохранены, начальный patch в артефактах.
